# 艾露莎注入器 — 插件开发文档 v1.0

> 目标游戏：世間知らずの猫エルーシャ (RPG Maker MV, EnigmaVB, NW.js 0.93)
> 注入器版本：v1.0

---

## 一、概述

### 1.1 注入器做什么

艾露莎注入器在游戏启动时，将你写的插件 JS 文件加载到游戏中。支持两种模式：

| 模式 | 如何加载你的插件 | 适用场景 |
|------|-----------------|---------|
| **打包模式** (Game.exe) | Bootstrap：CreateFileW 重定向 → fs+eval | 玩家用 |
| **解包模式** (nw.exe) | 直接修改 `www/js/plugins.js` | 开发调试用 |

两种模式对你的插件代码**透明**——写一份 JS，两端都能跑。

### 1.2 玩家使用流程

```
玩家双击 ElushaInjector.exe → 导入 .elsmod → 开启开关 → 启动游戏 → 插件生效
```

你的工作：写出正确的 `.elsmod` 文件。

## 二、快速开始

### 2.1 最小可工作插件

创建文件 `www/js/plugins/HelloWorld.js`：

```javascript
// HelloWorld.js
/*:
 * @plugindesc 我的第一个插件
 * @author YourName
 */
(function() {
    alert('HelloWorld 已加载');
})();
```

创建 `www/js/plugins/data/HelloWorld_YourName/plugin.json`：

```json
{
  "name": "HelloWorld",
  "version": "1.0.0",
  "author": "YourName",
  "description": "弹出 HelloWorld",
  "gameVersion": "1.06"
}
```

在注入器中进入开发者模式，点击「打包 elsmod」→ 选择 `HelloWorld.js`，生成 `HelloWorld-1.0.0.elsmod`。发给玩家，玩家导入后即生效。

## 三、插件文件结构

### 3.1 开发目录

```
你的工作目录/
└── www/js/plugins/
    ├── MyPlugin.js              ← 你的插件代码
    └── data/
        └── MyPlugin_YourName/   ← 只有这个目录属于你
            ├── plugin.json       ← 必须：元数据
            ├── images/           ← 可选：图片资源
            ├── audio/            ← 可选：音频资源
            └── config.json       ← 可选：配置文件
```

**命名规则**：`data/<插件名>_<作者>/`。打包工具据此识别你的插件数据。

### 3.2 .elsmod 内部结构

`.elsmod` 就是 zip 压缩包。解压后：

```
MyPlugin-1.0.0.elsmod
└── www/js/plugins/
    ├── MyPlugin.js
    └── data/
        └── MyPlugin_YourName/
            ├── plugin.json
            └── images/
```

### 3.3 安装后布局

玩家通过 `ElushaInstaller.exe` 安装后，文件解压到游戏目录：

```
游戏目录/
├── Game.exe                      ← 游戏本体（名称可能不同）
├── ElushaInstaller.exe           ← 安装器（可选保留）
├── ElushaInjector.exe            ← 注入器 GUI
├── UninstallElusha.exe           ← 卸载器
├── _internal/                    ← 注入器运行库
├── version.dll                   ← 注入 DLL
├── elsmod_data/                  ← 数据目录
│   ├── injector_config.json      ← 注入器配置（自动生成）
│   ├── originals/                ← 原版文件备份
│   └── MyPlugin-1.0.0.elsmod     ← 你的插件包
└── www/js/plugins/
    ├── MyPlugin.js               ← 你的代码
    └── data/
        └── MyPlugin_YourName/    ← 你的数据
```

## 四、manifest.json 完整参考

`.elsmod` 包内必须包含一个 `plugin.json`。以下全部字段：

```json
{
  "name": "MyPlugin",
  "version": "1.0.0",
  "author": "YourName",
  "description": "一句话描述",
  "gameVersion": "1.051",
  "dependencies": [],
  "conflicts": [],
  "files": []
}
```

### 字段说明

| 字段 | 必填 | 类型 | 说明 |
|------|:---:|------|------|
| `name` | ✅ | string | 插件名。必须和 JS 文件名一致（不含 `.js`）。全局唯一。 |
| `version` | ✅ | string | 语义化版本。`1.0.0`, `2.1.0-beta` 等。 |
| `author` | ✅ | string | 作者名。同作者+同名 = 冲突。不同作者+同名 = 可共存。 |
| `description` | ✅ | string | 一句话描述你的插件做什么。 |
| `gameVersion` | ✅ | string | 支持的游戏版本。注入器不强制校验，但玩家可查看。 |
| `dependencies` | ❌ | array | 依赖的其他插件。见 §4.1。 |
| `conflicts` | ❌ | array | 冲突插件列表。见 §4.2。 |
| `files` | ❌ | array | 插件部署的文件列表。**如果不填，打包时自动推断。** 见 §4.3。 |

### 4.1 依赖声明

```json
{
  "dependencies": [
    { "name": "MiniMap", "author": "AuthorName", "version": ">=0.6.0" }
  ]
}
```

| 子字段 | 必填 | 说明 |
|--------|:---:|------|
| `name` | ✅ | 依赖的插件名 |
| `author` | ❌ | 不填=匹配任何作者 |
| `version` | ❌ | 运算符：`>=`, `<=`, `=` |

### 4.2 冲突声明

```json
{
  "conflicts": [
    { "name": "OldMapMod" },
    { "name": "BattleMod", "author": "SomeoneElse" }
  ]
}
```

导入时注入器会警告用户存在冲突。

### 4.3 files 字段

```
如果你不填 → 打包时自动扫描 data/ 目录下的所有文件并加入列表。
如果你填了 → 注入器按你的列表管理文件。升级时检查同名文件冲突。
```

用于声明插件拥有的所有文件。卸载时据此清理。

## 五、写插件 JS 代码

### 5.1 RPG Maker MV 插件规范

你的 JS 文件**必须**以 RMMV 插件头注释开头：

```javascript
// MyPlugin.js
/*:
 * @plugindesc 插件描述
 * @author YourName
 *
 * @param enableFeature
 * @desc 启用某功能
 * @type boolean
 * @default true
 *
 * @param language
 * @desc 语言设置
 * @type string
 * @default zh
 *
 * @help
 * 使用说明文字。
 */
```

`PluginManager.parameters('MyPlugin')` 读取参数：

```javascript
(function() {
    var params = PluginManager.parameters('MyPlugin');
    var enabled = String(params['enableFeature'] || 'true').toLowerCase() === 'true';
    var lang = String(params['language'] || 'zh');
    // 你的代码...
})();
```

### 5.2 可用的 NW.js API

NW.js 0.93 提供 Node.js API。你可以在插件中直接使用：

```javascript
// 文件系统
var fs = require('fs');
var path = require('path');
var content = fs.readFileSync('path/to/file.json', 'utf8');
var exists = fs.existsSync('path/to/file');

// 进程信息
var gameDir = process.cwd();  // 游戏目录

// 网络请求
var xhr = new XMLHttpRequest();
xhr.open('GET', 'js/plugins/data/MyPlugin_Author/config.json', false);
xhr.send();
```

**注意**：这些 API 在浏览器环境（非 NW.js）不可用。如果你要同时支持网页版 RPG Maker MV，需要做环境检测。

### 5.3 数据文件路径

游戏运行时 `www/` 为根目录。访问你的数据文件：

```javascript
// 读取 data/MyPlugin_Author/config.json
var xhr = new XMLHttpRequest();
xhr.open('GET', 'js/plugins/data/MyPlugin_Author/config.json', false);
xhr.send();
var config = JSON.parse(xhr.responseText);

// 使用 fs（NW.js 可用）
var fs = require('fs');
var config = JSON.parse(fs.readFileSync('www/js/plugins/data/MyPlugin_Author/config.json', 'utf8'));
```

**路径规则**：
- `/` 不用 `\`
- 以 `js/plugins/` 开头（不是 `www/js/plugins/`）
- `fs` 路径可以用 `www/js/plugins/...`

## 六、Bootstrap 加载机制

### 6.1 打包模式下插件如何加载

```
Game.exe 启动
  → version.dll 加载
  → 读 injector_config.json
  → CreateFileW 重定向：EventInformation.js → EventInformation_bootstrap.js
  → Bootstrap.js 执行：
    ① fs.readFileSync("elsmod_data/originals/.../EventInformation.js") → eval  ← 原版照跑
    ② fs.readFileSync("www/js/plugins/MyPlugin.js") → eval                     ← 你的插件
    ③ fs.readFileSync("www/js/plugins/AnotherPlugin.js") → eval                ← 另一个插件
```

**对你意味着什么**：
- 你的 JS 代码被 `eval()` 执行（和 RMMV 的 `PluginManager.loadScript` 效果一样）
- `PluginManager.parameters()` 正常工作（因为插件的 `/*:` 头注释被 RMMV 在启动时解析过了）
- 你的代码在 NW.js 的全局作用域中运行
- 解包模式和打包模式行为一致——不需要写两份代码

### 6.2 main.js 注入模式（备选）

注入器另一种模式：在 `main.js` 的 `PluginManager.setup($plugins)` 之前插入 `$plugins.push({"name":"MyPlugin",...})`。VFS fallback 机制让游戏从磁盘找到你的 JS 文件。

## 七、开发工作流

### 7.1 解包模式开发（推荐）

```bash
# 1. 解包游戏
evbunpack Game.exe output/

# 2. 在解包目录工作
cd output/www/js/plugins/
# 创建 MyPlugin.js, data/MyPlugin_Author/plugin.json

# 3. 手动将插件加入 plugins.js 的 $plugins 数组末尾
# 4. 运行 nw.exe 测试
```

### 7.2 打包模式测试

```bash
# 1. 打包你的插件
ElushaInjector.exe --cli pack "www/js/plugins/MyPlugin.js"
# → 生成 MyPlugin-1.0.0.elsmod

# 2. 在原版游戏目录中导入
# 启动注入器 → 导入 → 启动 Game.exe
```

### 7.3 孤立启动（单插件测试）

```
注入器开发者面板 → 孤立启动 → 选择 .elsmod
→ 游戏只加载这一个插件 → 关闭后自动恢复
```

## 八、CLI 完整参考

所有命令都通过注入器 exe 运行：

```bash
ElushaInjector.exe --cli <命令>
```

### 插件管理

| 命令 | 说明 |
|------|------|
| `list` | 列出所有已安装插件 |
| `info <名称>` | 查看插件详情 |
| `enable <名称>` | 启用插件 |
| `disable <名称>` | 禁用插件 |

### 开发工具

| 命令 | 说明 |
|------|------|
| `pack <路径>` | 打包 JS 文件为 .elsmod。自动发现 data/ 目录 |
| `unpack <文件>` -o `<目录>` | 解包 .elsmod 到指定目录 |
| `template --name X --author Y --dir <目录>` | 生成插件项目模板 |
| `validate <文件>` | 验证 .elsmod 结构完整性 |

### 运行与配置

| 命令 | 说明 |
|------|------|
| `launch` | 启动游戏 |
| `config` | 查看当前环境信息 |
| `tools` | 列出推荐开发工具 |
| `register` / `unregister` | 注册/取消 .elsmod 文件关联 |

### 示例

```bash
# 打包
ElushaInjector.exe --cli pack "d:\dev\www\js\plugins\MyPlugin.js"
# 输出：MyPlugin-1.0.0.elsmod

# 验证
ElushaInjector.exe --cli validate "MyPlugin-1.0.0.elsmod"
# 输出：✓ 验证通过  名称: MyPlugin  版本: 1.0.0  作者: YourName  文件数: 3

# 生成模板
ElushaInjector.exe --cli template --name MyPlugin --author YourName --dir ./my_plugin
# 生成：my_plugin/www/js/plugins/MyPlugin.js + data/MyPlugin_YourName/plugin.json
```

## 十、FAQ

**Q: 为什么我的插件解包模式正常，打包模式不生效？**
A: 确认：
1. 注入器高级面板中「注入方式」选的是 `Bootstrap 替换` 或 `main.js 插入`
2. `elsmod_data/injector_config.json` 中 `plugins` 数组包含你的插件名
3. 游戏目录下 `version.dll` 存在

**Q: 我的插件需要覆盖游戏自带文件怎么办？**
A: 当前版本暂不支持。可以使用 `PluginManager` 的 Monkey Patch 方式在运行时替换游戏函数。

**Q: 多个插件之间如何通信？**
A: 使用全局变量或 `PluginManager._parameters`。NW.js 环境下也可以通过 `process` 共享数据。

**Q: 如何让插件只在特定条件下生效？**
A: 在插件代码开头判断条件，不满足就 `return`：

```javascript
(function() {
    if (!condition) return;
    // 正常逻辑...
})();
```

**Q: 打包时提示 "未找到匹配的 data 目录"？**
A: 确认 `data/` 下存在 `<JS文件名>_<作者>/` 目录，且其中有 `plugin.json`。目录名必须严格匹配——空格、大小写都算。
