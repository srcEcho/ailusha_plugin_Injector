# 艾露莎注入器 v1.0 — 设计文档

> 状态：设计定稿 | 2026-08-08

---

## 一、产品定位

- **名称**：艾露莎注入器 (Elusha Injector)
- **版本**：1.0
- **支持游戏版本**：1.051（主页面标题栏展示，不做校验）
- **对标游戏**：世間知らずの猫エルーシャ (EnigmaVB + NW.js 0.93 + RPG Maker MV)
- **普通用户**：双击打开，开关插件，启动游戏。不需要说明书。
- **插件开发者**：CLI 驱动，所有功能可通过命令行调用。AI 友好。

## 二、插件格式 `.elsmod`

- **本质**：zip 压缩包
- **内部结构**：
  ```
  PluginName.elsmod
  ├── www/
  │   └── js/
  │       └── plugins/
  │           ├── <PluginName>.js        ← 插件本体
  │           └── data/
  │               └── <PluginName>_<Author>/   ← 插件数据（必须以此格式命名）
  │                   └── plugin.json    ← 元数据（必须）
  ```

### 2.1 plugin.json 规范

```json
{
  "name": "QuestLog",
  "version": "2.0.0",
  "author": "QuestMod",
  "description": "任务引导系统。按 Q 打开任务日志。",
  "gameVersion": "1.051",
  "dependencies": [],
  "conflicts": []
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 插件唯一标识 |
| `version` | ✅ | 语义化版本 |
| `author` | ✅ | 插件作者 |
| `description` | ✅ | 简介 |
| `gameVersion` | ✅ | 支持的猫游戏版本 |
| `dependencies` | 否 | 依赖列表 |
| `conflicts` | 否 | 冲突列表 |

### 2.2 依赖/冲突格式

```json
{
  "dependencies": [
    { "name": "MiniMap", "author": "elusha_mod", "version": ">=0.6.0" }
  ],
  "conflicts": [
    { "name": "OldMapMod" }
  ]
}
```

- `name`：必须
- `author`：可选（不填 = 匹配任何作者）
- `version`：可选（`>=` / `=` / `<=`）

### 2.3 为什么 plugin.json 放在 data/名称_作者/ 下

不同作者可能制作同名插件。`plugin.json` 放在 `data/<PluginName>_<Author>/` 下实现作者级隔离，避免互相覆盖。

### 2.4 插件命名冲突

- **同一作者、同名插件 → 版本共存**。UI 下拉选择激活版本。老版本 elsmod 保留在 `elsmod_data/`。
- **不同作者、同名插件 → 拒绝并提示**"名称冲突。建议联系作者在名称中标注作者后缀"。

### 2.5 标准项目模板

`--cli template --name <n> --author <a> --dir <d>` 生成：

```
<指定目录>/
└── www/
    └── js/
        └── plugins/
            ├── <插件名称>.js
            └── data/
                └── <插件名称>_<作者>/
                    └── plugin.json
```

打包时严格按此结构检测。格式不符 → 拒绝打包并提示具体问题。

## 三、目录结构

```
游戏目录/
├── Game.exe                       ← 游戏本体（可能为 nw.exe 或其他名称）
├── ElushaInstaller.exe            ← 安装器（用户下载的唯一文件，可选保留）
├── ElushaInjector.exe             ← 注入器 GUI（Nuitka standalone）
├── UninstallElusha.exe            ← 卸载器（Nuitka standalone, tkinter）
├── python310.dll                  ← Nuitka 运行时
├── *.pyd / *.dll                  ← Nuitka 运行时模块（散落于 EXE 同级）
├── PySide6/ shiboken6/            ← Qt 库目录
├── tcl/ tk/ tcl8/                 ← Tcl/Tk 运行时（卸载器依赖）
├── injector/                      ← 嵌入资源（图标等）
├── version.dll                    ← 注入器核心 DLL（exe 内嵌，启动时解出）
├── elsmod_data/                   ← 全部状态集中于此
│   ├── registry.json              ← 注册表（导入记录 + 启用状态 + loadOrder）
│   ├── injector_config.json       ← 注入策略配置
│   ├── install_manifest.json      ← 安装清单（卸载器用）
│   ├── ui_config.json             ← GUI 配置（语言、主题、字体、选中 exe）
│   ├── tmp/                       ← 导入临时目录（事务性解压）
│   ├── QuestLog-v2.0.0.elsmod     ← 源文件（命名规则：{name}-{version}.elsmod）
│   └── ...
├── www/js/plugins/                ← 已安装插件（活动副本，从 elsmod 解压）
│   ├── QuestLog.js
│   └── data/
│       └── QuestLog_QuestMod/
│           └── plugin.json
└── ...
```

> **打包说明**：Nuitka standalone 编译为原生 EXE（Python→C→native），避免 PyInstaller bootloader 被 EnigmaVB 检测。代价是 DLL/pyd 散落在 EXE 同级（flat 布局），而非集中在 `_internal/`。

砍掉了 `.mod-manager/` 目录。`elsmod_data/` 是唯一的状态目录——保留它就是保留全部。

## 四、环境检测（启动时自动执行，无需用户确认）

```
ElushaInjector.exe 启动
  → 检测当前目录是否包含 Game.exe
  → 是游戏目录：
      → 创建 www/js/plugins/（如不存在）
      → 创建 www/js/plugins/data/（如不存在）
      → 创建 elsmod_data/（如不存在）
      → 创建 elsmod_data/tmp/（如不存在）
      → 解出 UninstallElusha.exe（如不存在）
      → 解出 version.dll（如不存在）
      → 扫描 elsmod_data/*.elsmod → 与 registry.json 比对
        → 有 elsmod 但 registry 无记录 → 自动恢复
        → 有记录但文件缺失 → 标记为"破损"
  → 不是游戏目录：
      → 弹窗 "请将本程序放到游戏目录下运行"
      → 退出
```

**Sync（`_sync_enabled_plugins`）** 在以下时机执行：GUI 启用/禁用插件、
GUI 启动游戏前、CLI `launch` 前。每次 sync：
- 打包版：写 `injector_config.json`（插件列表 + 重定向规则）→ 生成 bootstrap JS → 补齐 originals（磁盘副本 → 必要时从 Game.exe VFS 提取）
- 解包版：向 `plugins.js` 的 `$plugins` 数组追加/移除 mod 条目（文件存在性校验）

### 4.1 不一致检测与修复

- 启动时检测 `registry.json` 记录的 `files` 是否真实存在于 `www/js/plugins/`
- 存在记录但文件缺失 → UI 标记为"破损"（红色描边），开关禁用
- 提供"修复"按钮（位于开关左侧）：
  - `.elsmod` 源文件存在 → 从压缩包重新解压
  - `.elsmod` 不在但 JS 文件残留 → 扫描已有文件更新注册表
  - 都不存在 → 报错"无法修复"

### 4.2 卸载后重装恢复

如果用户卸载时保留了 `elsmod_data/`，重装注入器后：
- 启动时扫描 `elsmod_data/*.elsmod`
- 与 registry.json 比对 → 有 elsmod 但 registry 无记录 → 自动恢复注册表条目

## 五、游戏运行时的操作限制

Game.exe 在运行中时：
- **禁止**：导入、卸载、开关切换、排序调整、修复
- 任何修改操作均弹窗"请先关闭游戏"
- "关闭"按钮仍然可用（只退出注入器）

### 6.3 导入流程

```
用户触发导入
  → 解析 .elsmod → 读取 plugin.json
  → 检查必填字段 → 缺失则拒绝并提示
  → 检查目录格式 → 不符则拒绝并提示
  → 检查重复 → elsmod_data/ 已有同名+同版本 elsmod → 弹窗"已存在"
  → 检查冲突（同名+同作者 → 版本共存 / 同名+不同作者 → 拒绝）
  → 检查依赖 → 缺失则警告但仍允许导入（只是不能启用）
  → 解压到 elsmod_data/tmp/（临时）
  → 验证 tmp/ 内文件完整性
  → 移动到 www/js/plugins/（正式位置）
  → 复制 .elsmod 到 elsmod_data/（文件名为 {name}-{version}.elsmod）
  → 清理 tmp/
  → 更新 registry.json
  → 触发拓扑排序 → 更新 loadOrder
  → 刷新 UI
```

**事务性保障**：先解压到临时目录 → 验证通过 → 一次性移到最终位置。如果中间失败，删除 tmp 目录，不影响现有插件。

### 6.4 文件生命周期（卸载 → 重装 → 升级）

核心原则：`registry.json` 的 `files` 列表精确记录了"插件的哪些文件来自 elsmod"。不在列表中的都是用户数据。

**卸载时**：
```
遍历 record.files → 逐一删除 → 保留不在 files 列表中的任何文件
```
→ `data/名称_作者/` 下插件运行时产生的用户数据（存档、配置缓存）不丢失。

**重装/升级时**：
```
1. 遍历旧 record.files → 逐一删除
2. 解压新版本到 tmp/
3. 遍历新版本所有文件 → 逐一检查：
   → 如果目标路径已存在文件，且该文件不在旧 record.files 列表中
   → 这意味着新版本的文件踩到了用户数据
   → 报错，列出冲突文件名，拒绝操作
   → 提示"请联系插件作者"
4. 全部检查通过 → 移动到正式位置
5. 更新 record.files 为新列表
```
→ 用户在旧版本间积累的数据夹在 `files` 列表差集中，不受任何影响。
→ 文件冲突是插件作者的职责，注入器只负责检测和报错。

## 七、插件加载顺序

### 7.1 拓扑排序算法

```
导入/启用/禁用任意插件 → 触发 reorder：
  1. 读取所有 enabled 插件的依赖关系
  2. 建图 → Kahn 拓扑排序
  3. 检测循环依赖 → 有则列出循环路径，标记相关插件为"冲突"，禁止启用
  4. 将排序结果写入 registry.json 的 loadOrder 字段
  5. DLL 注入时严格按 loadOrder 生成 $plugins.push() 序列
```

### 7.2 手动微调

每个条目旁有 ↑↓ 按钮。用户可在拓扑排序基础上微调相邻顺序。**立即写入 registry.json**。下次触发 reorder 时拓扑排序结果覆盖手动调整。

### 7.3 依赖连锁

- **启用 A（A 依赖 B，B 未安装）**：拒绝启用，提示"缺少依赖：B"
- **启用 A（A 依赖 B，B 已安装但禁用）**：弹窗"B 将被一起启用。确认？"
- **禁用 B（A 依赖 B）**：弹窗"A 依赖 B，将一起禁用 A。确认？"
- **卸载 B（A 依赖 B）**：弹窗"A 依赖 B，将一起卸载 A。确认？"

## 八、安装器

`ElushaInstaller.exe`（约 50MB，用户下载的唯一文件）：

**多页面向导流程**（tkinter + ttk，clam 主题）：

```
Welcome ──→ SelectExe ──→ Confirm ──→ Progress ──→ Done
  欢迎页      选择游戏程序    确认摘要      进度条复制     完成
  选择语言    浏览 .exe      覆盖警告      后台线程      可选自删
```

- **Welcome**：欢迎标题 + 简介 + 语言切换（zh/en/ja，始终可见的语言栏）
- **SelectExe**：文件对话框选择游戏 exe，自动派生安装目录
- **Confirm**：安装摘要（游戏程序路径、安装目录），检测已有安装并警告
- **Progress**：进度条 determinate 模式 + 状态文字，关闭按钮禁用
- **Done**：成功/失败分支，可选删除安装器（自删 bat）

**技术细节**：
- 安装器内含完整的 `ElushaInjector/` 目录（Nuitka standalone 输出）
- 后台线程复制文件 → `queue.Queue` → 主线程 `after(50)` 轮询更新进度条
- 安装清单写入 `elsmod_data/install_manifest.json`，支持增量合并
- 解包模式下备份原版 `www/js/plugins.js` → `elsmod_data/originals/www/js/plugins.js`（安装时 `plugins.js` 必然是原版干净的）
- PyInstaller onefile 打包安装器（~50MB），Nuitka onefile 更小但 `include-data-dir` 行为不可靠
- 无需管理员权限

## 九、卸载器

`UninstallElusha.exe`（Nuitka standalone + tkinter，安装时释放）：

```
┌──────────────────────────────────────────────┐
│ 卸载艾露莎注入器                              │
│                                              │
│ 将卸载注入器和所有已安装 + 已下载的插件        │
│                                              │
│ □ 保留已下载的插件（保留 elsmod_data/）        │
│ □ 保留已加载的插件（保留 www/js/plugins/）     │
│                                              │
│         ┌──────────┐ ┌──────────┐            │
│         │ 确认卸载  │ │   取消   │            │
│         └──────────┘ └──────────┘            │
└──────────────────────────────────────────────┘
```

**清理策略（四层防护）**：

| 层 | 机制 | 作用 |
|----|------|------|
| 0. 插件清理 | 删除插件文件 + bootstrap JS；解包模式恢复 `originals/` 备份到 `plugins.js`，正则剥离残留 mod 条目 | 还原游戏原版状态 |
| 1. Manifest 清理 | 读取 `install_manifest.json`，逐项删除 | 精确删除安装器记录的文件 |
| 2. 模式匹配 Fallback | 扫描已知 Nuitka/PyInstaller 文件模式 | 兜底清理 manifest 遗漏的文件 |
| 3. 残留批处理 | 收集仍存在的注入器文件 → 写 bat → 循环删除 | 清理被自身进程锁定的 DLL/pyd |

**Layer 0 详解**：解包模式下，卸载器先从 `originals/` 恢复原版 `plugins.js`，再读取注册表找出所有 mod 插件名，用正则匹配 `"name":"插件名"` 剥离残留条目。这样即使 `originals/` 备份被污染，卸载后的 `plugins.js` 也是干净的。

**为什么需要第 3 层**：卸载器自身是 Nuitka 编译的 tkinter 程序，运行时加载了 `python310.dll`、`_tkinter.pyd`、`tcl86t.dll`、`tk86t.dll` 等。这些文件在进程退出前无法被 `os.remove()` 删除。bat 文件在进程退出后循环重试，直到全部文件删除成功后自毁。

删除清单：
- `ElushaInjector.exe`、`UninstallElusha.exe`、`ElushaInstaller.exe`
- Nuitka 运行时 DLL/pyd（python310.dll, _bz2.pyd, _tkinter.pyd, tcl86t.dll, vcruntime140.dll 等）
- Nuitka 运行时目录（PySide6/, shiboken6/, tcl/, tk/, tcl8/, injector/）
- PyInstaller 遗留目录（`_internal/`）
- `version.dll`
- `*_bootstrap.js`
- 插件文件（可选保留）、elsmod_data（可选保留）

## 十、DLL 运行时行为

### 10.1 version.dll（v54 生产版，MinHook + Bootstrap）

- 导出函数全部 `return 0`（不做 version 代理 → 无残留进程）
- MinHook 永久 trampoline：Hook `kernel32!CreateFileW` + `kernel32!ReadFile`
- CreateFileW 重定向：匹配的目标 JS → Bootstrap 加载器
- Bootstrap 机制：`fs.readFileSync(原版) → eval` + `fs.readFileSync(Plugin.js) → eval`
- 读取 `elsmod_data/injector_config.json` 获取重定向规则和插件列表（**文件缺失 = 零重定向 = 零注入**）
- 双模式：Bootstrap（默认）+ main.js 注入（备选，1.6 上实测不触发）

### 10.1.1 Bootstrap 原版文件（originals）获取链

Bootstrap 需要原版目标文件（如 `EventInformation.js`）才能「原版照跑 + MOD 追加」。
`_ensure_originals` 按顺序尝试四个来源：

| 优先级 | 来源 | 适用场景 |
|-------|------|---------|
| 1 | 同目录解包版 `www/js/plugins/` | 解包模式 |
| 2 | 兄弟目录 `解包/www/js/plugins/` | 开发环境（evbunpack 产物） |
| 3 | 项目根 `www/js/plugins/` | 源码开发 |
| 4 | **Game.exe 自身 EnigmaVB VFS 提取**（`evb_vfs.py`） | **用户机器上的打包版（最终兜底）** |

> 第 4 来源是 1.6 修复的核心：从 Game.exe 的 VFS 文件表（`EVB\x00` 魔数 + 节点表，
> 移植 evbunpack 0.2.6 / Apache-2.0）定位目标文件 offset/size，直接读出原字节。
> 本游戏 VFS 文件全部未压缩（stored==original），无需 aPLib 解压；压缩文件会记录
> 错误并跳过（bootstrap 的 try/catch 保证 MOD 仍然加载）。
> 提取发生在每次 sync（GUI 启动/启用插件/启动游戏前，CLI `launch` 前），
> 已存在的 originals 直接跳过，绝不重复提取、绝不覆盖。

### 10.1.2 Bootstrap 韧性

Bootstrap 模板中每个 `eval` 都包 `try/catch`：

```js
(function(){var f=require('fs'),p=require('path'),b=process.cwd();
try{eval(f.readFileSync(p.join(b,'elsmod_data/originals/www/js/plugins/{original}'),'utf8'));}catch(e){}
try{eval(f.readFileSync(p.join(b,'www/js/plugins/PluginA.js'),'utf8'));}catch(e){}
...
})();
```

原版文件缺失/损坏时，游戏仅失去该原版插件，MOD 插件照常加载；
单个 MOD 损坏也不会连累其后的 MOD。

## 十一、注册表

`elsmod_data/registry.json`——注入器唯一状态文件：

```json
{
  "version": 1,
  "loadOrder": ["MiniMap", "QuestLog"],
  "records": [
    {
      "name": "QuestLog",
      "author": "QuestMod",
      "version": "2.0.0",
      "enabled": true,
      "source": "elsmod_data/QuestLog-v2.0.0.elsmod",
      "installedAt": "2026-08-05T14:30:00",
      "files": [
        "QuestLog.js",
        "data/QuestLog_QuestMod/plugin.json",
        "data/QuestLog_QuestMod/quests.json",
        "data/QuestLog_QuestMod/routes.json"
      ]
    }
  ]
}
```

- `loadOrder`：DLL 严格按此数组顺序注入
- `source`：elsmod 文件名（`{name}-{version}.elsmod`）
- `enabled`：DLL 只注入此字段为 true 的插件
- `files`：相对于 `www/js/plugins/` 的文件列表，用于卸载和不一致检测
